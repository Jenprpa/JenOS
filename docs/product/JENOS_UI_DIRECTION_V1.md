# JenOS UI Direction v1

Status: Product direction

Sprint: 2.1 Owner Workflow Revision

Purpose:

Define the owner-facing visual and interaction direction before redesigning the UI.

No implementation in this document.

## Owner Feedback

The current UI is still not appealing enough for everyday use.

It feels too much like:

- technical prototype,
- developer tool,
- admin dashboard.

The owner wants something more personal, warm, and inviting.

## Desired Feeling

JenOS should feel:

- Thai-first,
- warm,
- calm,
- soft,
- charming,
- modern,
- friendly but not childish,
- personal,
- easy to open every day.

It should not feel like:

- enterprise project management software,
- Jira,
- admin panel,
- productivity pressure system,
- developer demo.

## Visual Language

Recommended direction:

- warm cream base,
- soft sage / mint accents,
- dusty pink / peach secondary accents,
- muted teal for important actions,
- rounded surfaces,
- gentle depth,
- comfortable Thai typography,
- friendly icons,
- subtle botanical or organic motifs,
- meaningful empty states.

## Information Hierarchy

Primary everyday UI:

```text
Projects
```

Secondary:

- quick capture,
- references,
- settings,
- technical information.

Technical status must not appear in normal owner UI.

If needed, place technical information in:

- developer/debug area,
- settings,
- hidden disclosure,
- dev-only route.

## Home Direction

Home should invite the owner back into active Projects.

It should answer:

- What Projects exist?
- Which Project needs attention?
- What can I open now?
- Can I quickly create a Project?

It should not start with:

- technical architecture,
- empty admin grid,
- global task count,
- mandatory capture field.

## Project Card Direction

Project cards should feel like living workspaces.

Possible signals:

- name,
- short boundary/description,
- current reality phrase,
- next movement hint,
- gentle dependency marker,
- recent evidence/event if useful.

Avoid:

- progress percentage,
- priority score,
- red pressure labels unless true risk exists.

## Empty State Direction

Empty state should be reassuring.

Example tone:

```text
ยังไม่มีโปรเจกต์ใน JenOS
เริ่มจากเรื่องหนึ่งที่อยากดูแลต่อเนื่องก็พอ
```

Do not imply the owner has failed to organize life.

## Icon Direction

Use friendly, familiar icons where helpful:

- plus for create,
- folder/document for files,
- link for links,
- user for people,
- clock/wait for dependency,
- leaf/spark only if subtle.

Avoid decorative clutter.

## Interaction Direction

- Progressive disclosure.
- Minimum fields first.
- Details grow inside Project.
- Unknowns are allowed.
- No guilt language.
- No system-scolding.
- Owner decisions should feel deliberate but lightweight.

## Design Guardrail

The UI should make JenOS feel like:

```text
a calm personal workspace for living Projects
```

not:

```text
a database that happens to have a nice color palette
```
