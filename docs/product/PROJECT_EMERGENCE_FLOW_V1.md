# Project Emergence Flow v1

Status: Sprint 2.0 definition

Purpose:

Define how something becomes a Project without forcing everything into Project shape.

## Principle

```text
Project should emerge, not be forced.
```

## Flow

```text
Captured situation
-> Owner reviews
-> Does this represent bounded responsibility/change?
-> YES: owner creates Project
-> NO: remains information/reference/context
-> UNSURE: remains unresolved without forced classification
```

## Captured Situation

Minimum information:

- raw description,
- captured time,
- source/evidence.

Optional:

- related document/resource,
- possible deadline,
- related person,
- note.

The captured situation is not automatically a Project.

## Owner Review

Owner sees:

- preserved facts,
- unknowns,
- possible interpretation,
- question: "Does this need managed responsibility?"

JenOS may suggest but must not decide.

## Project Test

Ask:

- Is there a desired change or outcome?
- Does it require repeated decisions or follow-up?
- Is there a boundary separate from other things?
- Does progress/state matter?

Not all answers must be yes.

If almost all are no, it should not become a Project.

## YES: Create Project

Required:

- owner confirmation,
- project name,
- boundary,
- source capture/evidence,
- initial known reality.

Optional:

- first movement,
- dependency,
- deadline,
- related person/resource/document,
- area.

Do not require a large setup form.

## NO: Remain Information/Reference/Context

Examples:

- saved PDF,
- note with no responsibility,
- information that may matter later.

Preserve only what has value.

Allow delete/archive.

## UNSURE: Remain Unresolved

Unknown classification is valid.

Rules:

- do not force Project,
- do not guilt owner,
- allow later review,
- preserve source.

## Evidence to Record on Project Creation

Record:

- source capture,
- owner decision,
- project boundary,
- initial known reality,
- unknowns,
- optional first movement.

## Anti-Patterns

Avoid:

- auto-creating Project from every capture,
- asking for all metadata before creation,
- turning people into Projects,
- treating reference material as responsibility,
- turning "maybe later" into hidden work.
