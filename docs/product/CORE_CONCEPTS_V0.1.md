# Core Concepts v0.1

เอกสารนี้วิเคราะห์ Domain Concept เบื้องต้นของ JenOS โดยยังไม่สร้าง Database Schema แบบตายตัว

ระวัง: `Task` ไม่ใช่ศูนย์กลางของ Domain Model

## Project

- ความหมาย: หน่วยหลักของชีวิตหรืองานที่มีทิศทาง สถานะ บริบท ความทรงจำ และผลลัพธ์ที่ต้องการ
- เหตุผลที่จำเป็น: เป็นศูนย์กลางของความหมายและการตัดสินใจ
- ตัวอย่าง: คศ.3, GLOBE, Antigravity, สุขภาพ, การเงิน, บ้าน
- ความสัมพันธ์: มี State, Decision, Deadline, Waiting, Risk, Document, Memory
- สิ่งที่ยังไม่แน่ใจ: ขอบเขตของ Project ควรเล็กหรือใหญ่แค่ไหน

## State

- ความหมาย: สถานะปัจจุบันของ Project หรือ Concept สำคัญ
- เหตุผลที่จำเป็น: บอกความจริงมากกว่า Done/Not Done
- ตัวอย่าง: Planning, Waiting, Blocked, Reviewing
- ความสัมพันธ์: เปลี่ยนผ่านด้วย Event, Decision หรือ Observation
- สิ่งที่ยังไม่แน่ใจ: State taxonomy ควรถูกกำหนดกลางหรือปรับตาม Project

## Action

- ความหมาย: การขยับที่มีบริบทและเหตุผล
- เหตุผลที่จำเป็น: ช่วยแปลง State เป็นการเคลื่อนไหวโดยไม่ทำให้ Task เป็นศูนย์กลาง
- ตัวอย่าง: โทรถามเอกสารที่ค้าง, ตรวจผลทดลอง, ขอข้อมูลเพิ่ม
- ความสัมพันธ์: อยู่ใต้ Project และอ้างอิง Decision, Blocker หรือ Milestone
- สิ่งที่ยังไม่แน่ใจ: Action ควรมีอายุสั้นแค่ไหนก่อนถูกทบทวน

## Decision

- ความหมาย: การเลือกที่มีผลต่อทิศทางของ Project
- เหตุผลที่จำเป็น: ต้องรักษาเหตุผลและผลกระทบของการตัดสินใจ
- ตัวอย่าง: เปลี่ยน Raspberry Pi เป็นอุปกรณ์อื่น, ลดขอบเขตบทที่ 4
- ความสัมพันธ์: สร้าง Memory, เปลี่ยน State, กระทบ Risk และ Action
- สิ่งที่ยังไม่แน่ใจ: Decision ระดับเล็กควรถูกบันทึกละเอียดแค่ไหน

## Context

- ความหมาย: ข้อมูลแวดล้อมที่ทำให้สิ่งหนึ่งมีความหมาย
- เหตุผลที่จำเป็น: ป้องกันการเห็นงานเป็นรายการโดด ๆ
- ตัวอย่าง: เวลาที่มี, พลังงาน, ภาคเรียน, คนที่เกี่ยวข้อง, ข้อจำกัดโรงเรียน
- ความสัมพันธ์: ใช้โดย Decision Support Layer และ Today Experience
- สิ่งที่ยังไม่แน่ใจ: Context ใดควรถูก capture อัตโนมัติ

## Person

- ความหมาย: บุคคลที่เกี่ยวข้องกับ Project หรือ Decision
- เหตุผลที่จำเป็น: งานจำนวนมากเดินหรือหยุดเพราะคน
- ตัวอย่าง: นักเรียน, ครูร่วม, ผู้ปกครอง, เจ้าหน้าที่, แพทย์
- ความสัมพันธ์: มี Role, Commitment, Waiting, Event
- สิ่งที่ยังไม่แน่ใจ: ควรเก็บข้อมูลส่วนตัวของบุคคลอื่นละเอียดแค่ไหน

## Role

- ความหมาย: บทบาทของบุคคลในบริบทหนึ่ง
- เหตุผลที่จำเป็น: คนเดียวอาจมีหลายบทบาทในหลาย Project
- ตัวอย่าง: เจ้าของ Project, ผู้ส่งข้อมูล, ผู้อนุมัติ, ผู้ร่วมตรวจ
- ความสัมพันธ์: เชื่อม Person กับ Project และ Commitment
- สิ่งที่ยังไม่แน่ใจ: Role ควรเป็น taxonomy กลางหรือเปิดให้ตั้งเอง

## Event

- ความหมาย: สิ่งที่เกิดขึ้นในเวลาใดเวลาหนึ่ง
- เหตุผลที่จำเป็น: เป็นหมุดของ Timeline และ History
- ตัวอย่าง: เด็กส่ง Dataset, ทดลองไม่ผ่าน, ได้รับหนังสือตอบกลับ
- ความสัมพันธ์: อาจเปลี่ยน State, สร้าง Memory, กระทบ Deadline
- สิ่งที่ยังไม่แน่ใจ: Event กับ Log ควรแยกกันชัดแค่ไหน

## Deadline

- ความหมาย: เวลาหรือวันที่มีผลต่อการตัดสินใจ
- เหตุผลที่จำเป็น: เป็นปัจจัยของ urgency แต่ไม่ใช่ priority ทั้งหมด
- ตัวอย่าง: ส่งเล่ม 27 ก.ค., นัดตรวจสุขภาพ, วันชำระเงิน
- ความสัมพันธ์: เชื่อมกับ Project, Commitment, Risk และ Today
- สิ่งที่ยังไม่แน่ใจ: Deadline แบบ soft กับ hard ควรถูกแยกอย่างไร

## Waiting

- ความหมาย: สถานะที่เรื่องหนึ่งหยุดเพราะรอสิ่งอื่น
- เหตุผลที่จำเป็น: แยกการรอออกจากความล้มเหลว
- ตัวอย่าง: รอเด็กส่งข้อมูล, รอกรมตอบ, รอใบเสนอราคา
- ความสัมพันธ์: ต้องมี Person หรือ Dependency, Reason, Review Date
- สิ่งที่ยังไม่แน่ใจ: Waiting ที่ไม่มีเจ้าของควรถูกจัดการอย่างไร

## Blocker

- ความหมาย: สิ่งที่ขวางไม่ให้ Project เดินต่อ
- เหตุผลที่จำเป็น: ช่วยอธิบายว่าทำไมงานไม่ขยับ
- ตัวอย่าง: ไม่มีผลทดลอง, ยังไม่ได้อนุมัติ, ข้อมูลไม่ครบ
- ความสัมพันธ์: เชื่อมกับ Waiting, Risk, Action และ Decision
- สิ่งที่ยังไม่แน่ใจ: Blocker ควรแยกจาก Dependency ที่ยังไม่พร้อมอย่างไร

## Resource

- ความหมาย: สิ่งที่ใช้ประกอบการทำงานหรือตัดสินใจ
- เหตุผลที่จำเป็น: Project ต้องอ้างอิงข้อมูลและเครื่องมือ
- ตัวอย่าง: ไฟล์, ลิงก์, งบประมาณ, อุปกรณ์, template
- ความสัมพันธ์: เชื่อมกับ Document, Project, Decision
- สิ่งที่ยังไม่แน่ใจ: Resource ควรมี version หรือไม่

## Document

- ความหมาย: เอกสารที่เกี่ยวข้องกับ Project
- เหตุผลที่จำเป็น: งานครูและงานโครงการจำนวนมากเดินผ่านเอกสาร
- ตัวอย่าง: เล่มรายงาน, ใบสมัคร, เอกสารประกวด, Google Drive file
- ความสัมพันธ์: เป็น Resource ชนิดหนึ่ง เชื่อมกับ Event, Decision, Deadline
- สิ่งที่ยังไม่แน่ใจ: Integration กับ Drive ควรเริ่มเมื่อใด

## Memory

- ความหมาย: ความทรงจำของ Project และระบบ
- เหตุผลที่จำเป็น: ช่วยให้ไม่ลืมเหตุผล ประวัติ และบทเรียน
- ตัวอย่าง: เหตุผลที่เปลี่ยนวิธีทดลอง, บทเรียนจากการส่งงานช้า
- ความสัมพันธ์: เกิดจาก Event, Decision, Observation, Lesson
- สิ่งที่ยังไม่แน่ใจ: Memory ใดควรถูกสรุปอัตโนมัติ

## Observation

- ความหมาย: สิ่งที่สังเกตเห็นแต่ยังไม่ใช่ข้อสรุป
- เหตุผลที่จำเป็น: แยกข้อมูลดิบจากการตีความ
- ตัวอย่าง: เด็กยังไม่ตอบ 3 วัน, พลังงานต่ำช่วงเย็น
- ความสัมพันธ์: อาจนำไปสู่ Inference, Risk หรือ Decision
- สิ่งที่ยังไม่แน่ใจ: Observation ควรถูก expire หรือไม่

## Lesson

- ความหมาย: บทเรียนที่สรุปจากประสบการณ์
- เหตุผลที่จำเป็น: ทำให้ History กลายเป็นความรู้
- ตัวอย่าง: งานที่รอคนอื่นควรมี review date เสมอ
- ความสัมพันธ์: มาจาก Memory, Event, Review
- สิ่งที่ยังไม่แน่ใจ: Lesson ควรผูกกับ Project หรือเป็น global knowledge

## Risk

- ความหมาย: สิ่งที่อาจทำให้ผลลัพธ์เสียหายหากไม่จัดการ
- เหตุผลที่จำเป็น: ระบบต้องไม่ซ่อนความเสี่ยงเพื่อให้รู้สึกดี
- ตัวอย่าง: ส่งเล่มไม่ทัน, ข้อมูลทดลองไม่พอ, สุขภาพทรุด
- ความสัมพันธ์: เชื่อมกับ Project, Deadline, Blocker, Today
- สิ่งที่ยังไม่แน่ใจ: ควรประเมิน risk ด้วย scale ใด

## Commitment

- ความหมาย: สิ่งที่ผู้ใช้รับปากหรือมีพันธะกับคน/เวลา/Project
- เหตุผลที่จำเป็น: ช่วยแยกสิ่งที่ต้องรักษาคำพูดออกจากสิ่งที่อยากทำ
- ตัวอย่าง: นัดส่งเอกสาร, รับปากตรวจงาน, นัดแพทย์
- ความสัมพันธ์: เชื่อมกับ Person, Deadline, Project, Today
- สิ่งที่ยังไม่แน่ใจ: Commitment ที่ไม่ชัดเจนควรถูก capture อย่างไร

## Energy

- ความหมาย: สภาพพลังงานหรือความสามารถของผู้ใช้ในช่วงเวลาหนึ่ง
- เหตุผลที่จำเป็น: การตัดสินใจที่ดีต้องคำนึงถึง human capacity
- ตัวอย่าง: วันนี้พลังต่ำ, มีเวลา 30 นาที, ป่วย
- ความสัมพันธ์: ใช้จัด Today และเลือก Action ที่เหมาะสม
- สิ่งที่ยังไม่แน่ใจ: ควรให้ผู้ใช้บันทึกเองหรือประเมินจากบริบท

## Review

- ความหมาย: การทบทวน Project, Waiting, Risk หรือ Decision
- เหตุผลที่จำเป็น: ทำให้ระบบไม่ปล่อยให้เรื่องค้างเงียบ
- ตัวอย่าง: ทบทวน Waiting ทุก 3 วัน, ตรวจ Sprint รายสัปดาห์
- ความสัมพันธ์: สร้าง Event, Lesson, State Change
- สิ่งที่ยังไม่แน่ใจ: Review cadence ควรเป็นค่า default หรือเรียนรู้จากผู้ใช้
