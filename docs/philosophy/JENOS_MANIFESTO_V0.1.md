# JenOS Manifesto v0.1

JenOS เชื่อว่าชีวิตไม่ควรถูกลดรูปเป็นรายการงานค้าง แต่ควรถูกมองเป็นระบบของโครงการ บทบาท ความสัมพันธ์ การตัดสินใจ ความทรงจำ ข้อจำกัด และพลังงานของมนุษย์

## Life Is Not a To-do List

ชีวิตไม่ใช่รายการงานที่ต้องทำให้หมด

ชีวิตประกอบด้วยโครงการที่มีทิศทาง บทบาทที่ต้องรับผิดชอบ คนที่เกี่ยวข้อง การตัดสินใจที่ต้องอธิบายได้ และสถานการณ์ที่เปลี่ยนตลอดเวลา

JenOS จึงไม่เริ่มจากคำถามว่า "เหลืองานอะไรบ้าง" แต่เริ่มจากคำถามว่า:

- ตอนนี้ชีวิตและโครงการต่าง ๆ อยู่ในสถานะใด
- อะไรควรได้รับความสนใจ
- อะไรยังรออยู่
- อะไรเป็นตัวขวาง
- การขยับเรื่องใดจะส่งผลดีที่สุดโดยไม่ทำร้ายชีวิตส่วนอื่น

## Everything Is a Project

สิ่งต่าง ๆ เช่น สุขภาพ การเงิน บ้าน รถ การสอน นักเรียน งานวิจัย การแข่งขัน เอกสาร และเป้าหมายชีวิต สามารถถูกมองเป็น Project ได้

Project ใน JenOS ไม่ใช่แค่กล่องใส่ Task แต่เป็นหน่วยของความหมายที่มี:

- Vision
- Current State
- Next Milestone
- Sprint
- Waiting
- Risk
- Definition of Done
- Memory

Project คือศูนย์กลางของบริบท ไม่ใช่ Task

## State Is More Important Than Task

Task เป็นเพียงกิจกรรมหนึ่ง แต่ State คือความจริงของโครงการ

ตัวอย่าง State ระดับแนวคิด:

```text
Exploring
Planning
Ready
In Progress
Waiting
Blocked
Reviewing
Completed
Paused
Archived
```

รายการนี้ยังไม่ใช่ข้อสรุปสุดท้าย และไม่ควรถูก hard-code จนกว่าจะมีหลักฐานจากการใช้งานจริง

## Every Project Has Memory

Project ต้องมีความทรงจำ ไม่ใช่มีแค่ไฟล์และรายการงาน

JenOS ควรรักษา:

- การตัดสินใจ
- เหตุผล
- สมมติฐาน
- ปัญหา
- การเปลี่ยนแปลง
- ผลลัพธ์
- บทเรียน

ให้คิดคล้าย Git History สำหรับชีวิตและงาน: ย้อนกลับได้ อธิบายได้ และไม่ปล่อยให้เหตุผลสำคัญหายไปอย่างเงียบ ๆ

## Everything Has Context

กิจกรรมหนึ่งไม่มีความหมายหากไม่รู้ว่า:

- อยู่ใน Project ใด
- ทำไปเพื่ออะไร
- เกี่ยวข้องกับใคร
- มีข้อจำกัดอะไร
- มีผลกระทบอย่างไร
- เกิดจากการตัดสินใจใด

Context ทำให้ JenOS ต่างจากรายการงานธรรมดา เพราะระบบไม่ได้มองแค่ว่าต้องทำอะไร แต่มองว่าทำไมสิ่งนั้นจึงสำคัญในเวลานี้

## Everything Is Connected

Project, Person, Role, Decision, Event, Document, Deadline และ Log สามารถเชื่อมโยงกันได้

JenOS จึงควรเติบโตไปทาง Jen Graph: เครือข่ายของสิ่งที่เกี่ยวข้องกันในชีวิตจริง ไม่ใช่ตารางงานแยกส่วน

## Never Ask "What Should I Do?"

JenOS ควรช่วยตอบว่า:

- ตอนนี้ควรให้ความสนใจกับอะไร
- เพราะเหตุใด
- สิ่งใดต้องตัดสินใจ
- สิ่งใดควรขยับ
- สิ่งใดกำลังรอ
- หากไม่ดำเนินการจะมีผลอย่างไร

ระบบไม่ควรสั่งแทนผู้ใช้ แต่ควรทำให้ผู้ใช้เห็นสถานการณ์ชัดพอที่จะตัดสินใจเอง

## History Is Gold

การเปลี่ยนแปลงทุกอย่างควรย้อนกลับและอธิบายได้

ประวัติไม่ใช่ภาระเอกสาร แต่เป็นความทรงจำของระบบ ช่วยให้ผู้ใช้ไม่ต้องเริ่มคิดใหม่ทุกครั้ง และช่วยให้การตัดสินใจในอนาคตมีบริบทมากขึ้น

## Life Before Productivity

เป้าหมายของ JenOS ไม่ใช่การทำงานให้ได้มากที่สุด

เป้าหมายคือการใช้เวลาและพลังอย่างมีความหมาย โดยไม่ทำลายสุขภาพ ความสัมพันธ์ ความสงบ และชีวิตของผู้ใช้

Productivity ที่ทำให้ชีวิตพังไม่ใช่ความสำเร็จของ JenOS

## Open Questions

- Project ในชีวิตจริงมีขอบเขตเล็กหรือใหญ่แค่ไหนจึงจะเหมาะสม?
- State ชุดแรกควรเป็นภาษากลางของระบบ หรือให้ผู้ใช้ปรับเองตั้งแต่แรก?
- Memory ควรถูกบันทึกละเอียดแค่ไหนโดยไม่กลายเป็นภาระ?
