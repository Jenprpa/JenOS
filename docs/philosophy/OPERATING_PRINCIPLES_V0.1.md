# Operating Principles v0.1

เอกสารนี้แปลง Manifesto และ Constitution ให้เป็นหลักการออกแบบที่ตรวจสอบได้

## Principles

1. ทุกคำแนะนำต้องมี Reason

   ผู้ใช้ต้องเห็นได้ว่าระบบเสนอสิ่งใด เพราะข้อมูลใด สมมติฐานใด และข้อจำกัดใด

2. ทุก State Change ต้องมี Timestamp และ Source

   การเปลี่ยนสถานะต้องบอกได้ว่าเกิดเมื่อใด และมาจากผู้ใช้ ระบบ integration หรือ AI suggestion

3. การเปลี่ยนแปลงสำคัญต้องมี History

   Decision, State, Risk, Deadline, Waiting และ Definition of Done ต้องไม่เปลี่ยนโดยไม่มีร่องรอย

4. ข้อมูลใหม่ที่ขอจากผู้ใช้ต้องสร้างคุณค่ามากกว่าภาระ

   ถ้าระบบถามเพิ่ม ต้องมีเหตุผลว่าข้อมูลนั้นช่วยตัดสินใจหรือช่วยลดความเสี่ยงอย่างไร

5. ระบบต้องรองรับ Undo หรือ Revision สำหรับการกระทำสำคัญ

   JenOS ต้องไม่ทำให้ผู้ใช้กลัวการแก้ไข เพราะการทำงานจริงเปลี่ยนแปลงได้เสมอ

6. ระบบต้องไม่แสดงข้อมูลทั้งหมดเมื่อผู้ใช้ต้องการเพียงสิ่งที่เกี่ยวข้องตอนนี้

   การแสดงทุกอย่างพร้อมกันคือภาระ ไม่ใช่ความชัดเจน

7. ระบบต้องแยก Urgency, Importance, Impact, Effort, Energy และ Risk

   Priority ต้องไม่ถูกลดเหลือคะแนนเดียวโดยไม่มีคำอธิบาย

8. Priority ต้องไม่คำนวณจาก Deadline เพียงอย่างเดียว

   งานใกล้ Deadline อาจไม่ใช่งานที่ควรขยับที่สุด หากถูก Blocked หรือใช้พลังเกินสภาพผู้ใช้ในขณะนั้น

9. งานที่ Waiting ต้องมีผู้ที่กำลังรอ เหตุผล และวันที่ควรตรวจสอบอีกครั้ง

   Waiting ไม่ใช่ Failure และไม่ควรถูกนับเป็นงานที่ผู้ใช้ต้องแบกทุกวัน

10. ระบบต้องเสนอการลดขอบเขต หยุด หรือพัก Project ได้

    บางครั้งคำตอบที่ดีไม่ใช่ "ทำให้เสร็จ" แต่คือ "ลดขอบเขต" หรือ "วางลงอย่างมีเหตุผล"

11. AI Suggestion ต้องไม่ถูกบันทึกเป็นข้อเท็จจริงโดยอัตโนมัติ

    สิ่งที่ AI เสนอเป็น Suggestion จนกว่าผู้ใช้หรือแหล่งข้อมูลที่เชื่อถือได้จะยืนยัน

12. ผู้ใช้ต้องเห็นได้ว่าอะไรเกิดจากผู้ใช้ อะไรเกิดจากระบบ และอะไรเกิดจาก AI

    Source attribution เป็นเงื่อนไขพื้นฐานของความไว้วางใจ

## Design Checks

ก่อนสร้างฟีเจอร์ใหม่ ให้ถาม:

- ฟีเจอร์นี้ช่วยตอบ Current State, Next Action หรือ Blocker หรือไม่?
- ฟีเจอร์นี้ลดภาระจริง หรือสร้างงานดูแลระบบเพิ่ม?
- ฟีเจอร์นี้ทำให้ผู้ใช้ตัดสินใจเองได้ดีขึ้นหรือไม่?
- ฟีเจอร์นี้มีทางย้อนกลับหรือแก้ไขหรือไม่?
- ฟีเจอร์นี้แยก Fact, Assumption, Inference และ Unknown ชัดเจนหรือไม่?

## Open Questions

- หลักการใดควรถูกบังคับในระดับ data model ตั้งแต่แรก?
- หลักการใดควรเริ่มเป็น guideline ก่อนแล้วค่อยเข้มขึ้นภายหลัง?
- Source ของข้อมูลควรถูกแสดงละเอียดแค่ไหนในประสบการณ์ใช้งานจริง?
